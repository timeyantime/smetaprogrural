# СметаHome — сметная программа ресурсного метода

**СметаHome** — локальное одностраничное веб-приложение для составления **локальных смет ресурсным методом (каркасный метод v2.0)**. Каждая строка сметы — это ресурс (затраты труда рабочих, эксплуатация машины, материал) с количеством и текущей ценой; все итоги — от строки до ИТОГО S = ПЗ + НР + СП + ЛЗ + Нал − Возвр (без НДС) — считаются автоматически и каскадно.

Приложение работает **полностью в браузере**: без бэкенда, без установки, без регистрации и без отправки данных куда-либо. Данные хранятся в `localStorage` браузера; обмен файлами — через экспорт/импорт JSON и CSV (Excel удалён).

## Быстрый старт

```bash
npm install        # установка зависимостей
npm run dev        # dev-сервер Vite → http://localhost:8080
```

Откройте браузер, добавьте раздел, впишите ресурсы (тип, количество, цену) — итоги, сводка ЗТ/ОМ/М, НР, СП и ЛЗ посчитаются сами. Работа автосохраняется в браузере.

## Запуск и сборка

### Вариант 1 — Vite (рекомендуется для разработки)

```bash
npm install
npm run dev          # dev-сервер с HMR: http://localhost:8080
npm run build        # продакшн-сборка в dist/
npm run preview      # локальный просмотр собранной версии из dist/
```

### Вариант 2 — любой статический сервер

Корневой `index.html` грузит ES-модули `src/js/*` напрямую, поэтому достаточно любого HTTP-сервера (ES-модули не работают по протоколу `file://`, открывать файл двойным кликом нельзя):

```bash
python3 -m http.server 8080     # или: npm run serve
# открыть http://localhost:8080
```

### Требования

- **Node.js ≥ 18** (для сборки и тестов; для «Варианта 2» — только сам браузер);
- современный браузер (Chrome / Firefox / Edge / Safari) с поддержкой ES-модулей;
- доступный `localStorage` (в приватном режиме некоторых браузеров автосохранение может не работать — приложение выводит предупреждение).

## Возможности

### Таблица ресурсов (грид)

Интерфейс повторяет паттерны **Airtable**:

- **Вкладки-разделы** сверху: каждый раздел сметы — как отдельная таблица; есть вкладка **«Все разделы»** (плоский список всех записей со сквозной нумерацией). Двойной клик по вкладке — переименование раздела; перетаскивание вкладок — изменение порядка разделов; кнопка «＋» — новый раздел.
- **Inline-редактирование**: двойной клик по ячейке открывает input с синей рамкой; Enter — сохранить, Esc — отменить, клик вне — завершить редактирование.
- **Чипы типов затрат**: цветные pill-метки с выпадающим меню — **ЗТ** (зелёный, затраты труда), **ОМ** (оранжевый, эксплуатация машин), **М** (фиолетовый, материалы); у машин дополнительно метка **Тмр** (оплата труда машинистов, флаг `operator`).
- ~~Сортировка~~ и ~~Группировка~~ — **удалены** (см. «⛔ Запрещено к разработке»): таблица всегда плоская, порядок строк только ручной.
- **Изменение ширины столбцов** перетаскиванием границы заголовка; ширина сохраняется в браузере (`smetapro.v4.cols`); сброс — в меню колонки (▾).
- **Контекстное меню строки**: изменить, дублировать, переместить вверх/вниз, удалить, применить цену из НСБ, копировать наименование.
- **Drag & drop строк** между разделами и перестановка внутри раздела.
- **Модальное окно записи** (двойной клик по номеру строки): расширенная карточка со всеми полями.
- **Подсказки ресурсов**: автоподбор типа и цены по названию из ранее введённых записей и из НСБ.
- **Строка добавления** внизу таблицы: «Нажмите, чтобы добавить запись…».
- Sticky-заголовок таблицы с иконками типов полей (T — текст, # — число, $ — деньги, ⬡ — выбор, ∑ — вычисляемое).

### Структура сметы: разделы и главы

- Добавление / удаление / дублирование / переименование разделов;
- **Главы** — объединение разделов в главу (`makeChapter`), повышение/понижение уровня (`promoteSection` / `demoteSection`), сворачивание глав;
- Перемещение разделов перетаскиванием вкладок;
- Сквозная нумерация строк (`№ п/п`) обновляется автоматически.

### Расчёт сметы

Каскадная модель: **стоимость строки → итоги раздела → сводка сметы**.

```
Стоимость строки        = Кол-во × Текущая цена
Итого по разделу        = Σ стоимостей строк раздела

Сводка по смете:
  ЗТ   (затраты труда / оплата труда рабочих) — строки type=labor
  ОМ   (эксплуатация машин)                  — строки type=machine
    ├─ Тмр (оплата труда машинистов)         — machine c operator=true
    └─ ОМ − Тмр (эксплуатация без машинистов)
  М    (материалы, конструкции, прочие)      — строки type=material

  ПЗ    = СУММА(q_факт × p_полн)         (прямые затраты; q_факт = q_нетто × (1 + k_отх))
  НР    = % × базу (ФОТ или ПЗ)          (накладные расходы, ставка настраивается)
  СП    = % × базу (ФОТ или ПЗ) + d_рын  (сметная прибыль + рыночная надбавка)
  ЛЗ    = ВЗ + ЗУ + Дож + ПП + Т_раб + Гарант + НП   (лимитированные; НП = 3% × (ПЗ + НР))
  Нал   = УСН 6% × S без налога          (без НДС)
  S     = ПЗ + НР + СП + ЛЗ + Нал − Возвр
```

> Каркасный метод v2.0: труд считается с наценкой ×1.20 на чел-ч (ночь/праздник — доп.
> множитель k_ночн), НДС исключён полностью, возвратные суммы (металлолом, ликвидация ВЗ)
> вычитаются из итога.

Базой для НР/СП может быть **ФОТ** (ЗТ + Тмр) или **ПЗ** — выбирается в сайдбаре сводки. Ставки НР, СП, настройки каркасного метода (ЛЗ, УСН, d_рын) редактируются прямо в интерфейсе; все настройки сразу пересчитывают смету. Боковая панель сводки показывает карточки ЗТ/ОМ/Тмр/М, ПЗ, НР/СП, разбивку ЛЗ, Налог (УСН), − Возвр и ИТОГО S; панель сворачивается кнопкой ◀/▶. В статус-баре всегда видны число разделов/записей, размер выделения, ПЗ и Итого.

### Округление по Методике 421/пр

Единый источник истины — `src/js/rounding.js` (Методика Минстроя России № 421/пр, п. 58, таблица 22):

- все промежуточные расчёты идут **с полной точностью**; округляется только итоговая статья;
- режимы точности: **копейки (2 знака)** / **рубли (0 знаков)**;
- методы: **математическое** (5 и выше — вверх), **банковское** (half-to-even), **отбрасывание остатка** (вниз).

### Диаграмма Ганта

- Длительность задаётся в столбце **«Длит., дн.»**; записи с длительностью **0 или пустой на диаграмму не попадают**;
- Полосы строк и **сводные полосы разделов** (раздел охватывает свои работы);
- Учёт активной вкладки: вид соответствует выбранному разделу;
- **Связи «предшественник → последователь»**: рисуются линии, предок удаляется в один клик;
- **Подсветка критического пути** — цепочка предшественников, определяющая минимальный срок;
- Перетаскивание полос мышью (сдвиг начала работ), масштаб по ширине дня, линейка дат;
- Экспорт диаграммы в **SVG** и **PNG** (`svgToPng` из `office.js`).

### Сводная ведомость ресурсов

Отдельная вкладка вида:

- плоский перечень **уникальных ресурсов по всей смете** (сведение дублей по наименованию/единице — это агрегация данных, а не UI-группировка; кнопки «По типу/По единице» удалены);
- поиск по ведомости;
- суммарное количество и **итоги по стоимости**.

### НСБ — нормативно-справочная база

Встроенная база расценок (шифр, наименование, единица, цена):

- добавление, редактирование, удаление записей НСБ; возврат к значениям по умолчанию;
- **импорт / экспорт НСБ в JSON**;
- **вставка расценки из НСБ в смету** (с сохранением шифра, наименования, единицы и цены);
- **массовое обновление цен** выделенных записей по данным НСБ;
- применение цены из НСБ к одной записи через контекстное меню;
- НСБ хранится отдельно от сметы (`smetapro.nsb.v1`) и переживает создание новых проектов.

### Выделение записей и пакетное редактирование

- Клик по номеру строки — выделение; Ctrl+клик — добавить/убрать; Shift+клик — диапазон;
- **Ctrl+A** — выделить все видимые, **Esc** — снять выделение, **Ctrl+D** — дублировать выделенное;
- Стоимость выделения показывается в сайдбаре и статус-баре;
- **Батч-бар** пакетного редактирования выделенных строк (цена, тип, ставка и т. п.) и «обновить цены выделенных из НСБ» одной операцией.

### Проверка ошибок (валидация)

Сервис `validation.js` проверяет проект, разделы, ресурсы, ставки НР/СП и параметры округления; проблемы классифицируются по severity и собираются в счётчик `problems`. Из панели проблем можно **перейти к конкретной ошибочной строке** (`goToProblem`). Типичные проверки: пустое наименование, нулевое/отрицательное количество, отсутствие цены, некорректные ставки процентов.

### Справочник методики

Кнопка в верхней панели открывает встроенный **Справочник** — подробную методику расчёта затрат (что такое ЗТ/ОМ/Тмр/М, как считаются ПЗ, НР, СП, ЛЗ, как выбирать базу начислений и режим округления) прямо в приложении, без внешних документов.

### Печать

- Выбор ориентации: **альбомная / книжная** (настройка запоминается в `smetapro.print.v1`);
- Печатается **текущий вид** — таблица сметы или диаграмма Ганта;
- Отдельная печать страницы (`printPage`) и печатная форма с полным набором столбцов; правила печати — в `src/css/style.css` (`@media print`).

### Сохранение, экспорт и импорт

- **Автосохранение** проекта в `localStorage` (с дебаунсом) + ручная кнопка **«💾 Сохранить»**;
- **Экспорт / импорт JSON** — полная резервная копия сметы (разделы, строки, ставки, округление);
- **Экспорт CSV** (разделители `;`, совместимы с редакторами таблиц) и импорт CSV;
- ~~Экспорт Excel~~ — **удалён** (см. «⛔ Запрещено к разработке»).
- **История версий** (`smetapro.history.v1`) — снимки проекта в localStorage;
- Компактный кодек **TOON** (`src/js/toon.js`) для табличных данных (НСБ, ресурсы, история): экономия ~40–60 % объёма localStorage против JSON при строгой обратимости (поля вне схемы сохраняются в хвостовом столбце `_`).

## Модель данных

JSON-экспорт проекта имеет вид:

```json
{
  "title": "Локальная смета № 1",
  "sections": [
    {
      "name": "Земляные работы",
      "resources": [
        {
          "basis": "ГЭСН 81-02-01-01-01",
          "name": "Затраты труда рабочих (Слесарь 4 разр.)",
          "unit": "чел.-ч",
          "qty": 10.5,
          "price": 250.0,
          "note": "",
          "type": "labor",
          "operator": false
        }
      ]
    }
  ],
  "rates": { "overheadPct": 15, "profitPct": 10, "base": "wages" }
}
```

- `type` — `labor` | `machine` | `material` (для сводки), у каждой строки есть стабильный `id`;
- `operator: true` у `machine` — оплата труда машинистов (Тмр);
- `rates.base` — `"labor"` (от ФОТ) или `"pz"` (от ПЗ) для начисления НР/СП;
- поля для Ганта: `days` (длительность, дни), `pred` (номер записи-предшественника), `startAt` (принудительное начало в днях от старта сметы).

Модели `Project` / `Section` / `Resource` (`src/js/models/`) инкапсулируют структуру, арифметику итогов и сериализацию; сервисы работают с ними, а не с «сырыми» объектами.

## Архитектура

```
┌────────────────────────────────────────────────────┐
│ index.html + Alpine (x-data="smeta()")             │
│   UI: грид, вкладки, Гант, НСБ, сводка, печать     │  ← src/js/app.js
├────────────────────────────────────────────────────┤
│ Модели: Project → Section → Resource               │  ← src/js/models/
├────────────────────────────────────────────────────┤
│ Сервисы (чистые функции, без DOM):                 │  ← src/js/services/
│   calculation · storage · validation · export      │
├────────────────────────────────────────────────────┤
│ Ядро правил: rounding.js (421/пр) · toon.js (код)  │  ← единый источник истины
├────────────────────────────────────────────────────┤
│ Утилиты: debounce/throttle · formatters · office   │  ← src/js/utils/, office.js
└────────────────────────────────────────────────────┘
```

Принципы:

1. **Один источник истины** для каждого правила (округление — только в `rounding.js`, ключи хранилища — только в `storage.js`).
2. **Сервисы не знают про DOM** — их можно тестировать изолированно (что и делают 100 тестов).
3. **Модели сериализуемы** — JSON-экспорт/импорт проходит через них, схема версионируется (`v3 → v4` автомиграция).
4. UI (`app.js`) только связывает события с моделями/сервисами и держит состояние вида.

## ⛔ Запрещено к разработке (Kanban, темы, Excel, сортировки/группировки)

Следующие возможности **удалены по требованию пользователя и запрещены к возврату**:

1. **Канбан-доска** — реализывать НЕЛЬЗЯ. Никаких досок, колонок «To do / In progress / Done», drag-and-drop карточек между статусами. Планирование работ выражается **исключительно** через диаграмму Ганта и разделы сметы.
2. **Тёмная/светлая тема** — переключателя нет и быть не должно; приложение использует единственную светлую тему. Не вводить состояние `darkTheme`, CSS-переменные тем, `prefers-color-scheme` и кнопки ☀️/🌙.
3. **Экспорт в Excel** — удалён (`exportToExcel`/SpreadsheetML из `services/export.js` и `office.js`). Обмен файлами — только JSON и CSV. Не возвращать кнопку «Excel» и генератор `.xls`.
4. **Сортировки** — запрещены (одноуровневые, многоуровневые, по колонкам). Порядок строк — только ручной: перетаскивание, кнопки ↑/↓, порядок разделов сметы. Не вводить `sortDescOrAsc*`, `addSortLevel`, флаги `col.sortable`.
5. **Группировки** — запрещены в таблице («Группировать ▾», сворачивание групп, итоги по группам) и в сводной ведомости ресурсов (по типу/единице). Списки плоские: `pagedRows` над `flatViewRows` → `filteredRows`; сводная ведомость — плоская таблица уникальных ресурсов. Не вводить `groupBy`, `summaryGroup`, `visibleGroups`, `groupedFlatRows`, `toggleGroupCollapse`.

Соответствующие UI-элементы убраны из `index.html`, методы и состояния — из `src/js/app.js`. При рефакторинге держать этот список закрытым.
