# СметаHome — сметная программа ресурсного метода

## Описание

Веб-приложение для составления локальных смет **ресурсным методом**. Каждая строка сметы — это ресурс (затраты труда рабочих, машина, материал, эксплуатационные затраты) с указанием количества и текущей цены. Итоги по разделам и по смете в целом считаются автоматически.

Стек: **Alpine.js** (реактивность на странице), HTML + обычный CSS/Tailwind. Данные хранятся в памяти страницы; экспорт/импорт — JSON и CSV.

## Структура документа

```
Смета
 └── Раздел (наименование работ / часть сметы)
      └── Строка ресурса (таблица ниже)
```

Итоги считаются каскадно: строки → разделы → смета.

## Столбцы таблицы ресурсов

| № | Колонка | Поле | Тип | Описание |
|---|---------|------|-----|----------|
| 1 | № п/п | `index` | число | Сквозная нумерация строк, обновляется автоматически |
| 2 | Обоснование | `basis` | текст | Шифр расценки/сборника (например, ГЭСН 81-02-01-01-01), ссылка на проектную документацию |
| 3 | Наименование работ и затрат | `name` | текст | Наименование ресурса или работы |
| 4 | Ед. изм. | `unit` | текст | Единица измерения (чел.-ч, маш.-ч, т, м3, м2, шт, компл.) |
| 5 | Кол-во | `qty` | число | Количество по калькуляции/расчёту |
| 6 | Текущая цена, руб. | `price` | число | Цена за единицу измерения на текущий момент |
| 7 | Стоимость, руб. | `total` | вычисляемое | `qty × price` (readonly) |
| 8 | Примечание | `note` | текст | Комментарий (источник цены, коэффициент и т. п.) |
| — | Действия | — | кнопки | Удалить строку, переместить вверх/вниз, дублировать |

## Итоговые строки

- **По разделу**: сумма стоимости (`total`) всех строк раздела.
- **По смете**: сводка
  - Затраты труда рабочих (оплата труда), руб. — строки типа `labor`;
  - Эксплуатация машин, руб. (ОМ) — строки типа `machine`, в том числе:
    - Оплата труда машинистов (Тмр) — строки `machine` с флагом `operator: true`;
    - Эксплуатация машин без оплаты труда машинистов (ОМ − Тмр);
  - Материалы, руб. (М) — строки типа `material`;
  - **Итого прямые затраты (ПЗ)** = ЗТ + ОМ + М;
  - Накладные расходы (НР), руб. — процент от ФОТ или ПЗ (настраиваемо);
  - Сметная прибыль (СП), руб. — процент от ФОТ или ПЗ + рыночная надбавка d_рын;
  - Лимитированные затраты (ЛЗ) = ВЗ + ЗУ + Дож + ПП + Т_раб + Гарант + НП (НП = 3% × (ПЗ + НР));
  - Налог (УСН) = 6% от S без налога, **без НДС**; Возвр — возвратные суммы (металлолом, ликвидация ВЗ);
  - **Итого по смете (каркасный метод v2.0)** = ПЗ + НР + СП + ЛЗ + Нал − Возвр.

## Типы ресурсов (для сводки)

В Alpine-модели каждой строке назначается `type` (выбирается вручную или автоподбором по названию):

- `labor` — затраты труда / оплата труда рабочих;
- `machine` — эксплуатация машин (флаг `operator: true` — оплата труда машинистов);
- `material` — материалы, конструкции, прочие.

## Управление

- Добавить/удалить раздел; добавить/удалить строку в разделе.
- Дублирование строки, перемещение строк вверх/вниз.
- Поиск/фильтр по наименованию и обоснованию.
- Сохранение в localStorage, экспорт/импорт JSON, экспорт CSV.
- Печать сметы (печатная форма таблицы со столбцами выше).

## Модель данных (JSON)

```json
{
  "title": "Локальная смета № 1",
  "sections": [
    {
      "name": "Земляные работы",
      "resources": [
        {
          "basis": "ГЭСН 81-02-01-01-01",
          "name": "Затраты труда рабочих (Слесарь 4 разр.)",
          "unit": "чел.-ч",
          "qty": 10.5,
          "price": 250.0,
          "note": "",
          "type": "labor",
          "operator": false
        }
      ]
    }
  ],
  "rates": { "overheadPct": 15, "profitPct": 10, "base": "wages" },
  "framework": { "enabled": true, "npPct": 3, "usnPct": 6, "dRyn": 0, "kNight": 1.3 }
}
```

> Примечание: `rates.vatPct` — legacy-поле из старого расчёта с НДС (каркасный метод v2.0 — «Без НДС»), в расчёте не участвует.

## Этапы разработки

1. Каркас страницы на Alpine.js: модель `smeta()` через `x-data`.
2. Таблица ресурсов с вычисляемой колонкой «Стоимость».
3. Разделы и их итоги.
4. Сводка итогов (labor / machine / material) + НР, СП, ЛЗ, Налог (УСН), Возвр — каркасный метод v2.0.
5. localStorage, экспорт/импорт, печать.

## UI в стиле Airtable (v2)

Интерфейс приложения повторяет паттерны Airtable:

- **Верхняя панель**: хлебные крошки «🗄️ СметаHome / <название сметы>», справа кнопки действий.
- **Вкладки разделов**: каждый раздел сметы — вкладка как таблица в Airtable; есть вкладка «Все разделы» (плоский список всех записей со сквозной нумерацией). Двойной клик по вкладке — переименование раздела, drag&drop по вкладкам — перестановка разделов, «＋» — новый раздел.
- **Тулбар**: поиск («Поиск записей…») в линии переключателя видов; счётчик скрытых фильтром записей — в статус-баре. ~~Кнопка «Группировать ▾»~~ — группировки запрещены (см. README «⛔ Запрещено к разработке»), таблица всегда плоская.
- **Сетка-таблица**: sticky-заголовок с иконками типов полей (T, #, $, ⬡, ∑), тонкие серые линии, подсветка строки при наведении.
- **Inline-редактирование ячеек**: двойной клик по ячейке → input с синей рамкой; Enter/Esc/клик вне — завершение.
- **Чипы single-select** для типа затрат: цветные pill-метки (ЗТ — зелёный, ОМ — оранжевый, М — фиолетовый) с выпадающим меню выбора; у машин — метка «Тмр».
- **Выделение записей**: клик по номеру строки выделяет запись (подсветка), Ctrl+A — выделить все видимые, Esc — снять; стоимость выделения показывается в сайдбаре. Ctrl+D — дублировать выделенную запись.
- **Модальное окно записи**: двойной клик по номеру строки открывает expanded record со всеми полями.
- **Строка добавления**: нижняя строка «Добавить запись · пустая строка в текущем разделе» + кнопка «⤢ Через форму» (как +Add row в Airtable).
- **Боковая панель сводки**: карточка стоимости выделения (появляется при выделении записей), статистические карточки ЗТ/ОМ/Тмр/М, ПЗ, НР/СП, ЛЗ (ВЗ/ЗУ/Дож/ПП/Т_раб/Гарант/НП), Налог (УСН), − Возвр с настройкой ставок, ИТОГО S = ПЗ + НР + СП + ЛЗ + Нал − Возвр; сворачивается кнопкой ◀/▶.
- **Статус-бар**: количество разделов/записей/выделения, счётчик скрытых фильтром, ПЗ и Итого по смете.
- ~~Итоги групп~~ — группировки запрещены; плоский список, итоги только общие (сайдбар/статус-бар).
